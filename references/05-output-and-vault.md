# 05 · 输出目录与落库（可选）

> 效力声明：本文件按节号递增顺序执行；评分分制与「单篇 / 完整模拟」口径以 `02-rubric.md` 为准，本文件只定"成品放哪、转写怎么归档、要不要落进笔记库"。

**先说清楚**：**输出目录约定是必做的**（第一节），与有没有笔记库无关；**落库是可选**的最后一步（第二节）——不配笔记库也能完整使用本 skill，成品留在 `work/` 下由教师直接取用即可。

## 一、输出目录约定（必做，与笔记库无关）

三份成品与中间产物默认落在同一个作业目录 `work/<日期>-<学生>/`：

```text
work/<日期>-<学生>/                     # 一次批改一个目录；--out 可改成任意路径
  <学生>-作业记录.md                     # 内部档案：原始分 + 映射分 + 逐项详评
  <学生>-家长.md                        # 家长版成品（纯文字）
  <学生>-学生.md                        # 学生版成品
  <学生>-底稿.md                        # 切问答 + 硬指标的中间产物
  <学生>-发音.md                        # 发音 provider 链报告（或 <转写名>-发音-ise.md）
  <文件名>--local.json                   # 引擎转写原文（统一 schema）
  raw/                                  # 引擎原始返回 + manifest（需要时）
    <文件名>--<引擎>-raw.json
```

约定：

1. **目录名用 `<YYYY-MM-DD>-<学生>`**：一次批改一个目录，便于整批归档或删除。
2. **中间产物与成品分开**：成品是给家长/学生的三份 `.md`；底稿、发音报告、转写 JSON 是中间产物，不外发。
3. **产物名固定**：成品为 `<学生>-作业记录.md` / `<学生>-家长.md` / `<学生>-学生.md`；转写为 `<文件名>--<引擎>.json`。
4. **改目录用 `--out`**：`scripts/kpf_asr.py` / `scripts/kpf_analyze.py` / `scripts/kpf_pronounce.py` / `scripts/kpf_report.py` 都接受 `--out <路径>`，默认即上面的 `work/<日期>-<学生>/`。
5. **转写原文随档案归档**：可读 `.md`（转写原句）与引擎原始 JSON 放在**同一个作业目录**（或该目录下的 `raw/`），作业记录里用相对路径或 wikilink 指向它——保证"报告里引用的原句能在转写里找到"（防编造校验就是按它比对的）。
6. **学生资料只留本机**：整个 `work/` 目录不进任何仓库、不上传公开服务；本地转写（`--engine local`）就是为此默认的，音频一旦切到 Groq / 讯飞就会上传，切换前先确认。

## 二、落库（可选）

**不做这一步也能交付**：三份成品已经落在 `work/<日期>-<学生>/`，教师直接取用即可。落库只是"把成品与错误卡顺手归进自己的笔记库"的可选动作——换一个库、甚至不用库，都不影响前面的流程。

### 2.1 库适配：使用者提供三样东西

本 skill **不绑定任何特定笔记库**（Obsidian / Logseq / 纯文件夹都行），也不硬编码任何目录名。要启用落库，使用者自备：

| # | 提供什么 | 说明 / 示例 |
|---|---|---|
| ① | **库根目录路径** | 你的笔记库根目录，如 `<vault-root>/`（写进你自己的流程说明即可） |
| ② | **产物 → 目标目录 的映射** | 每个产物落到库里哪个目录，例如：作业记录 → `<学生目录>/02-作业与提交/`；个人错误卡 → `<学生目录>/03-错误卡/`；班级共性卡 → `<班级错误目录>/`；转写归档 → `<原始资料目录>/` |
| ③ | **frontmatter 字段表** | 你的库用哪些字段（`type / 学生 / 班级 / 作业 / 状态 / 能力点 …`），以及各字段的取值枚举 |

**映射与字段表由使用者定义**；本 skill 只规定"落库必须分两阶段"这条纪律（2.2），不规定你的目录名。一份完整示例（作者本人那套目录树、映射与字段表）见 `docs/example-obsidian-layout.md`。

### 2.2 两阶段纪律（启用落库时必守）

1. **AI 只起草**：AI 起草的落库件一律先写进**待确认目录**（映射 ② 里指定的"草稿 / 待确认"位置），不直接进正式目录。
2. **教师确认后才进正式目录**：由教师（或教师明示授权）把草稿移进正式目录（映射 ② 里指定的"正式"位置）。
   > 例外：教师明确说"直接落库"时按其指示执行，但要告知已越此步，并留可回退说明。

每次落库的六个动作（**全部先落在待确认目录**）：

1. **作业记录**：起草一份完整初稿（分项评分表、硬指标表、逐项详评、教师观察、抽听点位表、家长反馈草稿、转化清单）。
   允许先落 `状态: 草稿` 再补分（草稿形态的校验见 2.3）。
2. **个人错误卡初稿**：一处主抓手一张卡（不是每个错误一张），状态建议从 `待复习` 起。
3. **共性卡初稿**：达到 2.4 的触发条件才起草，并在涉及学生的卡里注明互链。
4. **学生主页改动建议**：列出要加/改的内容（不改原文件，只出建议）——仅当你的库有学生主页时。
5. **转写归档**：可读 `.md` 与引擎原始 JSON 一起归档（见第一节第 5 条）。
6. **入库日志草稿**：追加一行 `日期 | 原件 | AI 建议 | 教师决定 | 最终位置`（"教师决定"列留空，等教师确认）；教师确认后回填后两列。

### 2.3 草稿形态（落库件可先落草稿，交付前必须转正式）

- 只对**作业记录**有效；家长版与学生版**没有草稿形态**（它们是要发出去的成品，占位符残留仍是 error）。
- `scripts/kpf_validate.py` 在草稿形态（frontmatter `状态: 草稿` 或校验时加 `--draft`）下只把**占位符残留**（`〔…〕`、`{…}`、裸 `待填`）从 error 降为 warning；**其余检查一律不变**：禁用词、引擎原始分、维度分范围、结构段齐备、单篇不给总分等都还是原级别。
- 草稿通过时 stdout 摘要会显式标注，例如
  `PASS 作业记录/单篇/B2 First · … · 0 error / 23 warning（草稿形态：占位符 23 处未填，交付前必须补全；转正式后这些是 error）`
  （这个数字取决于骨架里有多少个占位符，换模板就会变；`tests/fixtures/record_draft.md` 是仓库里可复现的那一份）
  —— **看到这行就说明它还不是可交付成品**。
- **交付前必须转正式**：填完全部占位符、把 `状态:` 改成正式状态（`待批改` / `已完成`），再按正式口径重跑一次（不带 `--draft`，且占位符 error 为 0），才算可交付、才能移进正式目录。

```bash
python3 scripts/kpf_validate.py <作业记录> --kind 作业记录 --form 单篇 --level FCE --draft
```

### 2.4 错误卡与班级共性卡

**个人错误卡**：状态 `待复习 → 复习中 → 已掌握`；升级条件要写清（例：下次作业仍保持每题 25 词以上、无 3 词以下答案 → 可改 `已掌握`）。

**班级共性卡的触发条件：同一个错误出现在 ≥2 名学生身上** → 从个人错误卡升级为班级共性卡：

1. 标题写清问题本质（如「口语答非所问（切题失准）」而不是「某某的错误」）。
2. 卡里放一张**班级画像表**：每个学生一行，列出该项中招情况与两项预估分。
3. 卡里必须写**可执行的课头操练**（3 分钟能做完的），否则这张卡没价值。
4. 个人错误卡留在学生目录，用链接互相指向。
5. 保留一个「待核实」小节：还有谁没交作业、需要优先检查。

> 触发条件的意义：三个人都犯的错就不再是个别学生问题，而是教学进度问题。累计到 3 人以上时，应建议安排一次专项课，而不是继续在批改里逐个提醒。

### 2.5 改正版作业怎么处理

学生重录后：

1. 转写归档到**同一作业目录**（加 `-改正版` 后缀），不要新建作业记录。
2. 在作业记录里加「改正版」一节：原版 vs 改正版对比表 + 反馈落地清单 + 重新评分。
3. 更新错误卡状态（`待复习 → 复习中`），并在复习记录里写明"哪几条已改对、哪几条仍未改、新增了什么"。
4. 给出**下次复查清单**，按优先级排序。
5. 这类"改正版"是验证教学有效性的最强证据，务必逐条核验，不要只重跑一遍分数。

### 2.6 交付前自检

按 `references/checklist.md` 逐项自检（全 skill 唯一一份清单）。本文件不再自带"隐私与提交前检查"清单；
落库相关的红线（学生资料只留本机、音频不上传公开服务、时间戳精确到 0.1 秒、草稿形态必须先转正式）
已并入该清单的 P0-12、P1-6、P1-7、P1-10、P2-1。
