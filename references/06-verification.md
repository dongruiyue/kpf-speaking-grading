> 效力声明：本文件按节号递增顺序执行；评分分制与「单篇 / 完整模拟」口径以 `02-rubric.md` 为准，本文件只记录实测结论与已知坑。
> 本文件记录这套 skill 的**实测结论**，不是设计意图。每次升级脚本后应更新。

## 二、跨引擎差异（做跨批次对比前必读）

同一条录音、同样的问题，两个引擎给出的数字**不一样**：

| 项目 | 外部转写服务 | large-v3-turbo | 影响 |
|---|---|---|---|
| 答题总词数 | 145 | 157（**+8%**） | 分词习惯不同（缩写词、连读的切分不一样），绝对词数不可跨引擎比 |
| 全片 ≥0.4s 停顿 | 24 处 | 8 处（**−67%**） | **停顿指标在 Whisper 下系统性偏少**：Whisper 的词时长是插值出来的，间隔被填得偏紧 |
| 念出的题目是否带问号 | 5 题全带 | 5 题里只 2 题带（**标点不可靠**） | 对齐算法绝不能依赖标点 |
| 词级置信度 | 无 | 有（216/216） | 发音疑点定位只能用本地引擎 |
| 成本 | 消耗额度 | 免费无限 | — |
| 音频 | 上传 | 不出本机 | — |

**统一性铁律**：同一个学生的跨批次对比（尤其"改正版 vs 原版"的进步曲线），**必须用同一引擎**。底稿 frontmatter 里记录了引擎名，数字可溯源。

建议：**长期固定用 `local`（large-v3-turbo）**——免费、隐私、有置信度。需要第二意见做交叉验证时再补跑一次云端引擎（`--engine groq`）。

## 三、必须知道的坑（都已修进脚本）

1. **macOS 系统代理**：系统代理指向未启动的代理程序时，pip / HuggingFace 下载直接超时。脚本已默认绕过；需要代理（如访问 Groq）时设 `KPF_USE_PROXY=1`。
2. **HuggingFace 直连超时**：默认走 `hf-mirror.com` 镜像；有科学上网时用 `KPF_HF_ENDPOINT=` 置空。
3. **bash 全角字符坑**：非 UTF-8 locale 下 bash 会把全角括号并进变量名（`$VAR）` 被当成变量 `VAR）`）。shell 脚本里变量后紧跟中文必须写 `${VAR}`。
4. **`tiny` 模型不可用**：实测对 L2 学习者语音的识别质量不足以支撑题目对齐（对齐度 0%，转出的是"what I used to see was your curry"这种）。**必须 `large-v3-turbo` 或更大**。
5. **题目对齐的三个必要条件**（每一条都是被真实数据打回后补上的）：
   - **不依赖 ASR 标点**：Whisper 常不给念出来的问题加问号，题干终点改由"最佳匹配窗口的右端"决定；
   - **窗口长度受限**（题目词数 ±3）：否则窗口起点前移也能拿高分，把题干切歪；
   - **滑窗相似度而非逐字匹配**：学生念题常改词，逐字匹配会整段失配；
   - **提前收的阈值要高（0.9）**：放宽到 0.75 时，前面一个"勉强像"的位置会抢掉后面"更像"的真位置（实测把答案段切少了 4 个词）。
   - **窗口下界要跟题目词数走**（2026-09-30 补，第 5 条）：下界原来是写死的 `i + 2`（最少 3 词窗口），于是 **1–2 词的题干永远对齐不上**（`Why?` 最高只能到 0.50 < 阈值）；现在下界是 `i + min(2, max(1, qlen) - 1)`。**那个 `min(2, …)` 夹子不能省**：直接用 `i + qlen - 1` 会让 `qlen ≥ 3` 的题目窗口下界变大、真位置被挤掉（实测同一批校准转写 6 道题里 4 道换位、2 道掉成"未定位"）。**1 词的题干属弱定位证据**（答案里出现同形词也会 100% 命中），底稿会为它单独加一条警告。
6. **题目未定位时不能让答案跑到文件末尾**：否则多道题的答案会退化成同一个巨型段落（实测 Q2–Q5 全变成 118 词）。现在**未定位的题不再整题跳过**（2026-09-30 修）：题干进不了底稿，但**答案区间要有着落** —— ① 前面没有已定位题（开场段）时，由 `[0, 下一已定位题起点)` **推断**该题答案区间并**计入答题合计**，报告里打 `†` 标注"可能含未识别的题干词、词数与语速只能当粗略参考"；② 中间/末尾的未定位题，其回答本来就落在前一题的答段里，**只报区间、不重复计入**（否则同一段词算两遍，合计能超过全篇词数）；③ 前后都没有已定位题时答案记空，并写明"无法推断"。三种情况各有一条明确的警告，**没有"跳过"这种静默处置**。

- [~] **真人校准：已做四轮盲判复测，但只有两轮是真盲——对外基线是「真盲第四轮」（2026-09-30 复测）** —— 外部真值用的是**剑桥官方发布的公开样题视频 + 配套官方给分文件**（公开视频，考官真实给分），共 **6 个 case / 16 个可比维度点**：FCE(B2) 两位考生、KET(A2) 两位考生、PET(B1) 两位考生（发音点一律是 AI 缺值，不计）；指标由 `scripts/kpf_calibrate.py` 算出。

  对照（**非盲**，只当"锚定效应有多大"的参照、不作结论）：**非盲一轮**（判官已知官方分，同一批语料）完全一致 **14/16 = 87.5%**、±1 档 **16/16 = 100%**、整体 **−0.06**。
  **读表前先记两句口径**：最后一列是 **`|差| > 1`（掉出 ±1 档的点数）**，不要与「`|差| ≥ 1 档`」混读——后者的口径下盲判一轮是 **11 条**（其中 9 条正好差 1.0）；`±1 档` 本身**包含完全一致**（0 与 ±0.5 都算在里面），**不能与"完全一致"相加**，校准器的表头写的就是「±1 档（含完全一致）」。
  **真正可比的只有「真盲一 ↔ 真盲四」这一对**（一 = 旧 rubric，四 = 现行 rubric）：完全一致 **12.5% → 18.8%**、±1 档 **87.5% → 93.8%**、平均带符号差 **−0.88 → −0.47**、掉出 ±1 档的点 **2 → 1**。即：**这一对只能读出"本轮复测的指标有改善"，读不出"那两处改动确实有效"** —— 四个真盲轮**每轮只有一个判官实例、而且互不相同**，所以「rubric 改动起效」与「这一轮判官手松/手紧」**分不开**；能确定的只有另一半：**37.5% 与 50.0% 是判官在量表里读到了答案，不是 rubric 的功劳**。
  **第四轮的逐点**（官方 → 盲判四轮；A–F 是六位考生的匿名代号，A / B / E / F 有话语组织，C / D 属 A2、只有语法与互动两项）：A 语法 −0.5 / 话语 −0.5 / 互动 0；B +0.5 / +0.5 / 0；C **−1 / −1.5**；D −0.5 / −1；E −0.5 / −0.5 / −0.5；F −1 / −1 / 0。**唯一掉出 ±1 档的是 C 的互动交际（官方 5 → 3.5）**。
  **一条工具边界（第四轮判官自己给出的解释）**：**A2 的互动交际在纯转写里基本测不到** —— A2 的判据只有"能不能维持简单交流 / 需要多少提示与支持"，而切分后的文本里**看不到考官提示了几次、沉默了多久**；C 的 −1.5 很可能主要是**证据缺失**，不是判错。只拿到纯转写时，A2 的互动交际宜标「待补」或明确标注为推断（判档提醒见 `references/02-rubric.md` 第四节）。**这条不只是提醒，它改变结论**：C / D 的那 2 个互动交际点按本 skill 自己的纪律**本来该标 `待补`**，却照样进了 16 点基线 —— **剔掉它们后 ±1 档 93.8% → 100.0%、偏差 −0.47 → −0.36；剔掉全部互动交际后完全一致率是 0/10**（三个"完全一致"的命中全在互动交际、且官方都给到 5 档，而 **AI 真正负责的语法与词汇 + 话语组织是 0/10**）。三组口径与复算命令（`--exclude 级别:维度`）见 `docs/calibration.md` 的「证据口径敏感性」。
  **残余偏差仍有方向**：A / D / E / F 多为 **−0.5**、B 为 **+0.5**，整体 **−0.47** —— **仍然偏严**（比 −0.88 好，但没有消掉）。**不要写成"已无系统性偏差"。**
  **下面「盲判三轮 / 二轮」两段、以及「二轮的一条发现」，都是污染轮的逐维度记录**（那两轮的量表里写着官方分与历轮结果）——**只当"泄漏能把数字撑到多高"的记录看，不作结论、不作基线、不作 rubric 效果的证据**；再往下那条「盲判一轮」是真盲，保留作旧基线。
  **盲判三轮的逐维度数字（污染轮）**：语法与词汇 **3/6 = 50.0%**（±1 **6/6 = 100%**，−0.08）、话语组织 **1/4 = 25.0%**（±1 **4/4**，−0.12）、互动交际 **4/6 = 66.7%**（±1 **6/6**，0.00）；`|差| ≥ 1 档` **0 条**。**三轮的逐点档位差分布**：**0.0 → 8 点 · ±0.5 → 8 点 · ≥1.0 → 0 点**——**剩下的 8 个不一致全部只有半档**（半档里**偏低 5 点 / 偏高 3 点**，**方向不一**），**整体平均偏差很小（−0.06 档），但这是正负抵消的结果**：按考生看，FCE 的第二位考生三项**全部高估 0.5 档**，而 FCE 第一位、KET 两位、PET 第二位各有 0.5 档的低估。所以只能说"**本批样本的整体平均偏差小**"，**不能**据此宣称没有系统性偏差，也**不能**把剩余的 0.5 档误差当成随机噪声——它可能是个案效应，需要更多判官或更多语料才能分辨；但这**不等于"已经达标"**——`1.0.0` 的门槛仍未达（见本条目最后一段）。`±1 档` 同样是**包含关系**——0 与 ±0.5 都算在它里面（8 + 8 = 16，正是 16/16 = 100.0%），**不能与"完全一致"相加**。
  **盲判二轮的逐维度数字（污染轮）**：语法与词汇 **1/6 = 16.7%**（±1 **5/6 = 83.3%**，−0.42）、话语组织 **2/4 = 50%**（±1 **4/4**，−0.25）、互动交际 **3/6 = 50%**（±1 **6/6**，−0.33）；`|差| ≥ 1 档` 只剩 **2 条**（其中 1 条正好差 1.0）。**逐点档位差分布**（它决定了"能不能相加"）：**0.0 → 6 点 · ±0.5 → 8 点 · ±1.0 → 1 点 · −1.5 → 1 点**（唯一超出 ±1 的点）。**`±1 档` 是包含关系**——0 与 ±0.5 都算在它里面（6 + 8 + 1 = 15，正是 15/16 = 93.8%），所以**它不能与"完全一致"相加**；校准器的表头写的也是「±1 档（含完全一致）」。
  **盲判一轮的数字（真盲 · 旧基线，保留作对照）**：完全一致 **2/16 = 12.5%**、±1 **14/16 = 87.5%**、整体 **−0.88 档（偏低）**；其中 `|差| ≥ 1 档` 共 **11 条**（9 条正好差 1.0）。逐维度：语法与词汇 **1/6 = 16.7%**（−0.83）、话语组织 **0/4 = 0%**（−0.75）、互动交际 **1/6 = 16.7%**（**±1 只有 4/6 = 66.7%**，**−1.00**）。**偏差以顶端为主、但中段也有，模式是"该给 5 时不给 5"**：16 个点**全部偏低或持平、0 点偏高**；官方 **5 档**的 11 个点贡献 **10.5/14 = 75%** 的绝对误差（三位被考官全给 5 的考生，盲判在语法与词汇 / 话语组织 / 互动交际上给成 4 / 4.5；KET 两位的互动交际被压到 3 与 3.5，差 −2 与 −1.5），官方 **3–4 档**的 5 个点里**有 4 个也不一致**、贡献 **3.5/14 = 25%**——**逐维度 `±1 档` 一致率 100%（语法与词汇 6/6、话语组织 4/4）只说明"没有差过一档"，不等于没有偏差**；**后续校准不能只盯 5 档**。
  **（污染轮）二轮的一条发现：锚点把顶端抬上来了，中段还是偏严**（这一轮的分数不作数，只留着看判官当时按表走到了哪一步）。PET 两位考生的六个点在一轮里全是 4 / 4.5 档，二轮升到 4.5–5 档、**没有再出现 4 档**，其中一位的三项**全部命中 5 档**、与考官完全一致；但**二轮唯一掉出 ±1 档的点，恰恰是中档考生的语法与词汇**——官方 3、盲判给 1.5（**−1.5 档**）。判官是**严格按表走的**：B2 语法词汇的 1 档**逐字等于** A2 的 5 档（"对简单语法形式有良好的掌控 + 日常情境一系列恰当词汇"），而这位考生**只满足后半个条件**（词汇够、形式控制不足），按偶数档口径落 1.5——**「半个条件满足」这类中段判法仍偏严，下一个杠杆在中段，不在顶端**。
  **这四条限制必须与上面的数字一起读**：① **每轮只有一个判官实例，而且四个真盲轮是四个不同的实例** —— 所以真盲一 ↔ 四 这一路里，"rubric 改动起效"与"这一轮判官手松/手紧"**分不开**；n = 1 只能看方向、**不能当精度指标**，要立住得同一批语料跑 2–3 个判官看分布。② **语料没变** —— 还是同 6 条 case 反复用，四轮都不是新样本（**多轮 = 同语料换 rubric 重判，不是多批独立样本**）。③ **低档（0–2）与发音维度仍然零覆盖** —— 就是下面边界 ① 与 ③ 的落点。④ **任何写进量表的校准数字都会污染盲判** —— 第 2、3 轮就是这么坏的：判官按流程一定要读量表，而量表里写着官方分与历轮结果（"三位被考官全给 5""11 个点是 5 档""中段轨迹 3 → 1.5 → 3.5"这类句子），于是**判官读到量表就读到了答案**；换判官实例、抹姓名、把上一轮产物挪出隔离目录，都堵不住这条路。**校准数字只写在 `docs/calibration.md`，量表（`references/02-rubric.md`）里一句不留**；判官读的是从量表生成的净化版副本，生成与自查办法见 `docs/calibration.md` 的「判档顺序」。
  **这几个边界必须与上面的数字写在同一条、一起读，缺一个就会读错结论**：① **样本严重偏上** —— 16 个官方分点**全部落在 3–5 档**、**0 个**落在 0/1/2 档，所以四轮都只验证了 **3–5 档这一带**；作者实际带的学生多在 1–3 档，**低档（0–2）仍然没有任何外部验证**。② **语法与词汇另有已识别的转写偏差，方向与幅度都未测量** —— 本机 whisper 会自动把学习者的错误改对（实测：官方评语引用的原句含三处错误，转写把它们改成了正确形式），所以转写比真实口语更正确；它对一致率的影响**可能美化、也可能加大偏差，方向与幅度都没有测量**，语法维度这一项的数字要按"已知有偏差、大小未知"来读。③ **发音维度仍是 0 校准** —— 这些是对话考试，而讯飞 ISE 是朗读型接口、必须有参考文本，本工具无法在对话录音上评发音：发音点**全部是"AI 缺值"**。④ **锚定效应已实测** —— 同一批语料，**知道官方分时完全一致率 87.5%（非盲），不知道时 12.5%（真盲一轮）/ 18.8%（真盲四轮）**（二、三轮的 37.5% / 50.0% 是污染数字，**不作锚定效应的证据**）：两组一起看，**知道分的那一组仍高于两轮真盲**；所以判档必须在看官方分之前完成（先只拿语料判档、写 `ai-分项.json`，判完再写 `teacher.json`；用隔离目录 + 姓名替换 + 保留文件 mtime 留证），并且**判官读的那份量表必须已抹掉校准数字**。⑤ **证据口径会改变结论（2026-09-30 新增）** —— 16 点基线里含 **2 个证据不足的点**（A2 的互动交际：纯转写里看不到考官提示了几次、沉默了多久，按本 skill 的纪律本该标 `待补`）。**剔除后 ±1 档 93.8% → 100.0%、偏差 −0.47 → −0.36；剔除全部互动交际后完全一致率是 0/10** —— 三个"完全一致"的命中全部来自互动交际（且官方都给到 5 档），**而 AI 真正负责的语法与词汇 + 话语组织是 0/10 完全一致**。复算命令（`--exclude 级别:维度`）见 `docs/calibration.md` 的「证据口径敏感性」。
  **还有一条：绿灯 ≠ 判分可用。** `±1 档` 的 80% 门槛太松——真盲**一轮**整体偏低 0.88 档、`|差| ≥ 1 档` 有 11 条，**却仍然算"绿灯"**（87.5% ≥ 80%）；真盲**四轮**同样是绿灯（15/16 = 93.8% ≥ 80%），而**完全一致率只有 18.8%**——**离"完全一致"差得更远**。**主指标应当是完全一致率与系统性偏差**，`±1 档` 只是"相邻档分歧在教学上是否可以接受"的旁证（阈值本身未改，改的是对它的读法）。
  **所以这不是"校准完成"——`1.0.0` 的门槛仍未达**：两轮真盲的对比是 **完全一致 12.5% → 18.8%、偏差 −0.88 → −0.47**（二、三轮的 37.5% / 50.0% 与被泄漏撑起来的 −0.06 不作数），方向是好的，但**幅度有限、残余偏差仍偏严**，而且 **n = 1、语料未换，仍只是方向性证据**；覆盖区间之外（0–2 档）与发音维度都还没有外部真值。**再加一条口径问题**：这 16 点里含 **2 个证据不足的点**（A2 的互动交际），剔除后 ±1 档变 100.0%、偏差 −0.36，而 **AI 负责的语法与词汇 + 话语组织是完全一致 0/10** —— 所以**报基线必须写全口径**（见上面边界 ⑤ 与 `docs/calibration.md` 的「证据口径敏感性」）。带名字的完整报告、音视频与转写留在仓库外的私有校准目录，不进仓库；做法见 `docs/calibration.md`。
- [ ] **模糊对齐的容差**：逐题词数存在 **±2–4 词**的边界误差（取决于题目与答案交界处的切分）。验收标准定为**逐题答词数相对人工基线的偏差 ≤5%**，整体量级可靠，单题词数应当作近似值。

### 题目对齐的假阳性风险（**下结论前必读**）

对齐算法把"最佳匹配窗口"当成学生念出的题干，因此有两类系统性噪声：

1. **上一题答案的尾部被并进题干窗口** → 会被报成"多读 X"。实测学生乙 `P56` 一课（2026-09-29）原版底稿里 Q1–Q5 的
   `多读 you. Music. / it's not boring. / music. / didn't. / piano.` **全部是这种假阳性**（都是上一题答案的末尾词）。
   2026-09-29 已改为**只在匹配窗口内部计算差异**（窗口首尾的纯插入先剔除），修复后同一份底稿 Q1/Q2/Q5 变成
   `逐字一致；交界处另有 N 词不在题干内，已忽略`，而真差异（Q3 漏读 `friends?`、Q4 `musical` 念成 `music`）仍被抓到。
2. **逐题词数 ±2–4 词误差**：交界处怎么切会直接影响单题词数。

结论：**念题差异告警与单题词数都不得单独作为结论**，必须回音频复核，或确认差异词落在题干中段而非交界处。

## 四之二、讯飞语音评测 ISE（xfyun）· 已接入并实测通过 ✅

脚本：`scripts/kpf_xfyun.py`；凭证在 `~/.kpf-speaking/config.json` 的 `xfyun` 块（appid / api_key / api_secret）。
端点：`wss://cn-east-1.ws-api.xf-yun.com/v1/private/s8e098720` —— 官方文档标注为「**中英文评测**」，控制台显示名「声通中文评测API」只是显示名，**传 `lang=en` 即评英文**。

**实测结果**（学生甲 `P102` 一课，5 句念题，耗时 8.4 秒）：

| 题 | overall | 发音 | 韵律 | 句末语调 | 语速 |
|---|---|---|---|---|---|
| Q1 | 75 | 79 | 89 | fall | 145 |
| Q2 | 77 | 72 | 87 | fall | 127 |
| Q3 | 80 | 76 | 89 | fall | 197 |
| Q4 | 81 | 87 | 90 | **rise** | 119 |
| Q5 | 85 | 83 | 92 | fall | 111 |

顺带抓到一个真实发音问题：Q4 是 `Which do you like best…`（特殊疑问句应降调），他念成了**升调**。这类"语调错位"是纯人工听音容易漏掉、而接口直接给出的信号。

**接入时踩到的 4 个坑（都已修进脚本）**：

1. **`parameter.st.result` 是必填块**，缺了服务端直接返回 `10106 wrapper output data invalid(key or type)`；且必须放在 `st` 里面——放到 `parameter` 层会报 `10163 unknown field`。正确写法：`"result": {"encoding":"utf8","compress":"raw","format":"json"}`。
2. **是"发完再收"的流式模型**：逐帧等响应会一路等到超时（实测第 2 帧起服务端就不回了，只在最后统一返回）。必须先把音频帧全部发完，再统一接收结果。
3. **首帧 status=0（开始）与末帧 status=2（结束）不能是同一帧**：音频短到只有一帧时服务端收到后直接断连（close 1000，无任何返回）。脚本强制拆成至少两帧。
4. **`.mov` 容器的 `seek` 会静默失效**：切片会从 0 秒解起，片段变成 `[0, end]`（Q2 实际传了 33 秒、Q5 传了 121 秒），评分结果全错但接口不报错。现在改为**不 seek、从头解码 + 按采样数精确切片**，并加了 `MAX_WAIT`/`MAX_FRAMES` 双上限防止一条坏音频挂死整批。

**返回结构**（易错点）：分数在 `payload.result.text` 经 base64 解码后的 **`body["result"]`** 里，不在顶层；顶层是 `recordId` / `refText` / `eof` / `params` 等元信息。

**额度**：控制台显示剩余服务量 1000 次（一次 = 一句）。一页 5 题 = 5 次，够约 200 页。

## 四之三、两个讯飞引擎的实测对比 —— 同一条录音

脚本：`scripts/kpf_ise_stream.py`（流式版）+ `scripts/kpf_xfyun.py`（suntone）。样本仍是学生甲 `P102` 一课的 5 句念题。

| 指标 | **suntone**（声通） | **流式版**（讯飞自研） |
|---|---|---|
| 总分 total | **79.6** | **61.3** |
| 发音／准确度 | 79.4（发音） | 62.2（准确度） |
| 韵律／标准度 | 89.4（韵律） | 58.6（标准度） |
| 流利度 | 95.6 | 85.2 |
| 完整度 | 92.8 | 92.6 |
| **教学映射 0–5** | **3**（79.6 落在 70–79 档） | **2**（61.3 落在 60–69 档） |
| 耗时（5 句） | 8.4 秒 | 12.3 秒 |
| 输出格式 | JSON | XML |
| 乱读拒识 / 音频诊断 | 无 | ✅ 全部"正常"、未乱读 |

**同一段录音，两个引擎差 18.3 分、映射到 0–5 差整整两档。** 这是本 skill 最需要注意的一致性问题：换个引擎就等于换了一套给家长的说法。

> 上表的 0–5 是**统一后的教学映射**（`kpf_xfyun.to_band()`：≥90→5、80–89→4、70–79→3、60–69→2、<60→1）。
> 2026-09-29 之前 suntone 用的是 ≥85→5 / ≥75→4 / ≥65→3 / ≥50→2，79.6 会被映射成 4；现已按
> `02-rubric.md` 的书面阈值统一为 3。**旧批次的映射值不要与新批次直接对比。**

**为什么差这么多，以及该信谁：**

- 差在**"标准度"**：流式版给 58.6，它的官方定义是「发音习惯符合英语母语标准（**无中式口音**），能灵活运用连读、重读、失音、爆破」。
- 而**剑桥的发音维度看的是 intelligibility（可理解），明确不因口音扣分**。用"像不像母语者"当标尺，会系统性压低分数，和家长/考试目标不匹配。
- 佐证：speaking 教师本人对这名学生的判断是"口齿不清"。流式版（准确度 62 / 标准度 58）与这个判断吻合，suntone（发音 79 / 韵律 89）偏宽松。

**结论（已写进 SKILL.md）**：

- **suntone 作主评分引擎**——口径与剑桥一致（重韵律、语调、可理解性），且能限定英式 `en_br`。
- **流式版作质检引擎**——只在分数异常或怀疑学生乱读时跑一次，看 `is_rejected` 与 `except_info`。
- **两者绝不可混用出分**。

**接流式版时又踩到的 2 个坑（都已修）**：

1. **接收帧数上限必须显著大于音频帧数**：服务端为每个音频帧回一条 `status=1` 的确认（`data` 为 null），最终结果才带 `status=2`。8 秒音频约 40–52 帧，上限设成 40 就永远收不到结果，而且**不报错**，只是 scores 全为 None。现设为 500。
2. **分数不在 `read_sentence` 节点上**：XML 结构是 `xml_result → read_sentence`（只有 lan/type/version）`→ rec_paper → read_chapter`（**分数在这里**）`→ sentence → word → syll → phone`。按标签名猜一定取不到分，必须按"谁带 `total_score` 属性"来定位。

另外 `except_info` 的取值含义（已内置解析）：`0x7001` 无语音/音量过小、`0x7004` 乱说、`0x7008` 信噪比低、`0x7012` 录音截幅、`0x7011` 没有音频输入。`is_rejected=true` 时官方明确说"分值不能作为参考"。

### 8.1 两个校验器（都只用 Python 标准库，离线、不联网、不用凭证、不读 `~/.kpf-speaking/config.json`）

| 脚本 | 作用 | 判据 |
|---|---|---|
| `scripts/kpf_validate.py` | 单个报告文件是否合规 | **有 error → 退出码 1**；warnings 只打印；明细走 stderr（带行号），stdout 一行摘要 |
| `scripts/check_consistency.py` | 规则本身有没有漂移（阈值 / 满分 / A2 维度数 / 防编造阈值 / 家长版技术指标分级 / 维度中英对照 / 引用完整性 / 节号连续 / 四节档位表结构） | 14 项断言（10 组），任一不成立 → 退出码 1 并打印两边取值 |

关键检查项（`--kind 家长`）：禁用词 13 个 + `AI`；技术指标**分两档**——无条件 error 的 8 个
（`词/分`、`词／分`、`词每分`、`词/分钟`、`词／分钟`、`个词`、`字数`、`平均每题`）与「停顿 / 语速」这两个
**带量化才算技术指标**的（同行有数字、或 次数/次/处/占比/%/百分之/每秒/每个/秒 落在 ±12 字符内 → error，
否则 warning）；`N/100` 引擎原始分；缺「本次评分」段；缺免责句（一字不改）；
`--form 单篇` 时拦 `得分率`/`总分`/`/ 45`/`/ 30`/`/ 60`/`未达`/`合格水平`/`过没过`/`量表分`
（**「总分」的唯一豁免是免责句本身**）；维度分必须在 0–5 且为整数或半步；
按 `--level` 校验维度行齐备（维度名中文官方译名与英文原名等价；A2 Key 不得有「话语组织」/`Discourse Management` 维度行）；
markdown 表格；`〔…〕`、`{…}`、`待填` 占位符残留（**作业记录草稿形态下降为 warning**，见 8.4）。
给 `--transcript` 时启用**防编造**：把报告里 `他说的 X 应为 Y` 的 X（以及逐句修改表的原句列）归一化后
在转写稿词序列里模糊查找，相似度 **< 0.85 → error**、**0.85–0.92 → warning**、**≥ 0.92 通过**，
边界可用 `--quote-threshold` / `--quote-warn-threshold` 覆盖。
**家长版/学生版不给 `--transcript` 是 error**（防编造"没跑过"不能与"跑过且通过"长得一样；`--no-transcript-check` 可显式关掉，关掉会在 stdout 摘要里标注）；另外**核心维度（语法与词汇、话语组织）写「待补」在家长/学生版是 error、作业记录只 warning**（真正缺测的是发音与互动交际）。

### 8.3 已知边界（下次改校验器前先看这里）

1. **防编造只覆盖"引用式原句"**（`应为`/`改后` 结构 + 逐句修改表原句列），不是全文英文都查——
   表扬段里那种带引号的原话不进硬校验，避免与"FCE Trainer Test 1"这类报告自带的英文标题混淆。
2. **防编造阈值 0.85 / 0.92 的取舍**（`QUOTE_ERROR` / `QUOTE_PASS`）：逐字照抄 1.00、只差标点 0.99、
   少一处词 0.93 全部通过；**在同一句真实句子里换掉一个词 0.82 现在是 error**（旧阈值 0.72 时只 warning、
   拦不住——这正是本次提高阈值的理由）；完全编造 0.68 仍是 error。
   代价是"报告把学生语法顺手改对"的引用（约 0.85–0.92）会落到 warning，需要人回查——这是有意的：
   宁可让人抄原文，也不放过编造。
3. **「总分」在单篇家长版里一律 error，唯一豁免是免责句**（正则 `不作为考试总分预估`）。
   想允许"等完整模考再算总分"这类前瞻句式，得再加一条正面豁免，否则照样报错。
4. **图片类题型只做弱提示**（warning）：没图片时"不得评描述完整性"这条，静态文本查不出真相，只能靠人。
5. **家长版禁用词里 `数据`、`样本`、`测量` 是无条件 error**，不随「停顿 / 语速」放宽——
   它们是"能看出有工具链参与"的词，教师不会自然这么写。若哪天要放开，改 `BANNED_PARENT`。
6. **技术指标的量化判定是"数字必须紧挨这个词"**，不是"整行有数字"：
   `几乎没有停顿` 稳过、`停顿 12 次` 稳拦、`5 道题全程没有沉默，几乎没有停顿` 也稳过（5 是题数）。
   `个词` 同理要求带数字（`18.8 个词` 拦、`三个普通的词` 放过）。
