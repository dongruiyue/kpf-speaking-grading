# 对外讲解材料 · 索引与讲稿

这套材料是给**"要把 kpf-speaking-grading 讲给别人听"**的人用的：它是什么、凭什么可信、怎么用、什么时候不能用、还差什么。全篇可离线讲，不需要联网、不需要现场花收费额度。

## 怎么用这套材料

| 场合 | 读哪篇 | 怎么用 |
|---|---|---|
| 15 分钟口头介绍 | 本文件第二节 | 照讲稿骨架讲，跳过现场演示 |
| 30 分钟带演示 | 本文件第二节 + 第三节 | 现场跑 `make check` 与"通过 / 拦截"对比 |
| 别人自己看 | `01` → `05` 顺序 | 每篇独立可读，文末有上一节 / 下一节 |
| 你准备被追问 | 本文件第四节 | 十二条预判问答与应答口径 |

配套文档：`README.md`（安装与完整命令）、`SKILL.md`（agent 流程说明）、`references/`（规则细则）、`docs/calibration.md`（校准方法与数据）、`docs/xfyun-setup.md`（讯飞开通指引）。

## 一页速览（可直接当封面页）

**一句话**：把 KET / PET / FCE 口语作业的音频或视频丢进来，本机转写 → 按剑桥口径诊断 → 生成「作业记录 / 家长版 / 学生版」三份成品 → 交付前用校验器把"合规"变成退出码。

| 维度 | 事实 |
|---|---|
| 覆盖级别 | KET(A2) / PET(B1) / FCE(B2)；A2 只有 3 个评分维度，没有「话语组织」 |
| 流水线 | 6 步，其中 5 步有脚本；剩下的是五件判断与把关的事（见 `03-usage.md` 第六节） |
| 机检闸门 | 发布前 4 道（`make check`）+ 每份报告 1 道合规校验 |
| 速度 | 一页 5 题约 140 秒录音：转写约 47 秒（8GB M2 / CPU int8），全流程约 1 分钟 |
| 成本 | 转写免费无限（本机，音频不出机器）；发音评测有免费额度，一页 5 题消耗 5 次 |
| 判档准确度 | 对官方考官分：完全一致 **3/16 = 18.8%**、±1 档 **15/16 = 93.8%**、整体偏严 **−0.53 档**（真盲第五轮，样本仅 6 case / 16 点）——**它真正负责的语法与词汇 + 话语组织两维只有 1/10 完全一致**；而"**同语料换一个判官，16 个点里 10 个会动 0.5 档**"就是当前判档的噪声量级 |
| 成熟度 | 规则与脚本已被独立审计多轮并收敛；版本 0.9.0，**1.0 门槛未达**（低档与发音维度仍无外部真值） |

**三条边界，开口就要说**：

1. AI 只评「语法与词汇」「话语组织」两项；**发音分不由 AI 给** —— 来自语音评测引擎，或老师听点位后手填。
2. 独自录音 / 自问自答**不评「互动交际」** —— 没有对手方就没有证据，给分就是编。
3. 单篇作业**只给分项分**（每维度 `X / 5`），不给加权总分、不给得分率、不判过没过。

## 三、现场演示清单（三条命令，全部离线、秒级）

演示原则：**不要展示"AI 说了什么"，要展示"校验器拦住了什么"**。这套东西的说服力在闸门，不在生成。

```bash
cd <repo>

# ① 四道闸门一次跑完：语法编译 + 规则一致性 + 31 个夹具回归 + 发布闸门
make check
#   预期：31/31 个用例与期望表一致；14 项断言全部成立；发布闸门 0 处命中

# ② 合规的家长版 → PASS；踩红线的家长版 → FAIL 并打行号
python3 scripts/kpf_validate.py tests/fixtures/parent_pass_fce.md --kind 家长 --form 单篇 --level FCE
#   预期：rc=0，PASS … 0 error / 0 warning
python3 scripts/kpf_validate.py tests/fixtures/parent_fail_speed_quantified.md --kind 家长 --form 单篇 --level FCE
#   预期：rc=1，逐条带行号 —— L16 [error] 家长版出现带量化的技术指标「语速」

# ③ 规则漂移会被抓住：改一个阈值再跑一致性检查
python3 scripts/check_consistency.py        # 预期 rc=0，「14 项断言全部成立」
#   在临时副本里把 kpf_xfyun.py 的 BANDS 里 90 改成 85，再跑一次 →
#   报「1 项不一致 / 13 项通过」并 rc=1（演示完把改动撤掉，别在真仓库上改）
```

`tests/fixtures/` 里 31 个用例都是匿名静态文本，所以演示不需要学生音频、不需要任何 key。

## 四、预判问答（十二问）

**Q1：这不就是让 ChatGPT 批口语吗？**
区别有三点：一是**发音有外部标尺**——AI 拿不到音频，分数来自语音评测引擎，不靠猜；二是**规则在文件里**，有 14 项一致性断言盯着阈值和维度不许漂移；三是**成品要过校验器**才能交付，防编造（引用的学生原句必须能在转写里找到）就是硬校验。裸模型三样都没有。

**Q2：准不准？**
对剑桥官方公开样题里考官给的档：完全一致 18.8%、相邻一档以内 93.8%。所以它的定位是**相邻档级别的判断**，不是考官分。三层要说清：**一是样本只覆盖 3–5 档，1–2 档没验证过；二是它真正负责的语法与词汇 + 话语组织两维只有 1/10 完全一致；三是同一批语料换一个判官，16 个点里 10 个会动半档** —— 也就是说，它给的分只可信到"相邻半档"这个粒度，而且**单次的那个分数别太当真，看它给的理由能不能落到证据上更靠得住**。具体见 `05`。

**Q3：会不会替代老师？**
不会，也不该。它替代的是五件机械活：听写誊录、算指标、找证据、套模板、查格式。定档、判断互动交际、决定怎么跟家长说，仍然是人。

**Q4：学生录音安全吗？**
默认路径全在本机：本地 whisper 转写，**音频不出机器**。只有两种情况会上传——用云端转写引擎，或用讯飞做发音评测——这两条都在配置与文档里明确标注了，用不用由你决定。

**Q5：要不要花钱？**
转写免费无限（本机算力）。发音评测走讯飞语音评测，注册即有免费额度（一次 = 一句，一页 5 题 = 5 次）。不配任何 key 也能跑完整流程，只是发音分要老师手填。

**Q6：为什么发音分不让 AI 给？**
两个理由：AI 手里只有转写文字，**根本没有音频证据**；而且"发音 4 分"这种数字一旦由语言模型生成，就是编数据。所以 AI 的输出被限制成"带时间戳的抽听点位表"，分由引擎或人给。

**Q7：为什么单篇作业不给总分、不判过没过？**
剑桥官方明确说口语原始分不能预测真实考试分数（口语只占考试的一部分）。给一个"总分"就是把局部当整体，家长会当成结论。只有覆盖全部 Part、四项齐备的完整模拟才给总分。

**Q8：家长的反馈是机器写的，家长能看出来吗？**
家长版有一组硬红线，校验器强制检查：不放引擎原始分（如 `93.6/100`）、不放带量化的技术指标（语速 X 词/分、停顿 X 次、词数）、不出现 `AI / 引擎 / 评测 / 识别 / 转写 / 数据` 等字眼、不用 markdown 表格、单篇正文除免责句外不得出现「总分」二字。自检口径是：**念一遍，既要听得出"这是老师给的分"，又不能听得出"这是机器分析出来的"**。

**Q9：那为什么还要老师改措辞？**
因为它只保证"合规"，不保证"贴切"。骨架给你把证据、分数、结构摆好，最后一段"接下来重点 / 回家怎么配合"必须由老师写——那句话决定家长会不会配合。

**Q10：一个班几十个人，会不会很慢？**
一页约 140 秒的录音，本机转写约 47 秒、全流程约 1 分钟。瓶颈其实在老师改措辞，而不在机器。规则固化之后，同类问题换一个学生也是同一套说法，这比"每次重新想怎么说"省得多。

**Q11：跨批次能看进步吗？**
能，但有硬前提：**同一个学生的前后对比必须用同一个转写引擎**。同一个学生同一段录音，两个引擎的答题词数能差 8%、停顿数差 67%——换引擎对比出来的"进步"是假的。所以底稿 frontmatter 记录了引擎名，数字可溯源。

**Q12：现在最缺什么？**
**真实批改案例**。目前的准确度账是用剑桥公开样题（含官方给分）算的，只有 6 个 case / 16 个点，而且全落在 3–5 档；作者实际带的学生多在 1–3 档，低档和发音维度都还没有外部真值。把真实的"老师怎么判"喂进来，才能继续校准——路径见 `05` 第七节。
